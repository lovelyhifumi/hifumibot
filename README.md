# 디스코드 유튜브 알림 봇

여러 서버와 채널에서 유튜브 새 영상 알림을 설정할 수 있습니다. 서버별 채널 ID와 유튜브 채널 ID는 환경변수에 넣지 않습니다.

## 설치 및 기존 봇 교체

1. 기존 봇 프로세스를 종료한 뒤 이 패키지의 파일로 교체합니다. `subscriptions.py`도 함께 복사하세요.
2. Python 3.10 이상에서 `python -m pip install -r requirements.txt`를 실행합니다.
3. 기존 `.env`를 같은 폴더에 두거나 `.env.example`을 `.env`로 복사하고 `TOKEN`을 입력합니다. 이전 `DISCORD_*_ID`, `YOUTUBE_CHANNEL_ID`는 더 이상 사용하지 않습니다.
4. 봇을 서버 설치 방식으로 초대합니다. Discord Developer Portal의 OAuth2 URL Generator에서 `bot`, `applications.commands`를 선택하고 다음 권한을 부여하세요: 채널 보기, 메시지 보내기, 메시지 기록 보기, 링크 삽입. 채널별 권한 덮어쓰기도 확인하세요.
5. `python bot.py`로 실행합니다. 슬래시 명령어가 반영된 뒤 원하는 채널에서 등록합니다. 일반 운영에서는 `TEST_GUILD_ID`를 비워 두세요. 개발 중에는 서버 ID를 넣어 해당 서버에 명령어를 동기화할 수 있습니다.

Message Content 특권 인텐트는 사용하지 않습니다. 봇이 보낸 자신의 알림 메시지만 중복 판정에 사용합니다. 모든 슬래시 명령어는 `유튜브`로 시작합니다.

## 명령어

| 명령어 | 동작 | 권한 |
| --- | --- | --- |
| `/유튜브등록 채널:@핸들` | 실행한 채널에 새 영상 알림 등록. 채널 주소·UC로 시작하는 ID도 가능 | 실행 채널의 채널 관리 권한 |
| `/유튜브해제 채널:@핸들` | 지정한 유튜브 알림 해제 | 실행 채널의 채널 관리 권한 |
| `/유튜브목록` | 현재 채널의 등록을 채널명과 링크로 확인 | 누구나 |
| `/유튜브도움말` | 사용 안내 | 누구나 |
| `/유튜브핑` | 응답 확인 | 누구나 |

관리자도 설정할 수 있습니다. 일반 텍스트 채널만 지원하며 DM·스레드·포럼은 등록 대상이 아닙니다. 한 채널에 여러 유튜브 채널을 등록할 수 있고, 같은 소스를 여러 서버·채널에서 구독할 수 있습니다. 명령어 응답은 실행한 사용자에게만 보이며, 등록 안내와 실제 알림은 채널에 표시됩니다. 자동 멘션은 하지 않습니다.

## 중복 방지

- 마지막 영상 ID를 파일에 기록하지 않습니다.
- 등록 완료 안내에 조회한 최신 영상 한 건의 제목과 링크를 확인용으로 표시합니다. 등록 시 목록 전체는 최초 기준 목록으로 저장하므로 확인용 항목이 자동 알림으로 다시 발송되지 않습니다. 재등록도 같은 방식입니다.
- 실제 발송 여부는 **이 봇이 해당 채널에 보낸 메시지의 임베드 푸터**에서 소스와 항목 ID를 읽어 판단합니다. 일반 대화, 다른 봇, 다른 유튜브 채널의 메시지는 기준으로 삼지 않습니다.
- 시작 후 첫 확인에서는 등록 이후의 기록 전체를 읽습니다. 이후에는 메모리 캐시와 새 메시지 조회를 사용합니다. 재시작하면 Discord 메시지에서 다시 복구합니다. 마지막 발송 ID를 디스크에 기록하지 않습니다.
- 목록 순서가 바뀌거나 발송한 항목이 재등장해도 재전송하지 않습니다. 기록 조회가 실패하면 해당 채널 발송을 건너뜁니다. 일부 발송 후 실패하면 다음 확인에서 성공한 메시지를 확인해 남은 항목을 발송합니다.
- 같은 소스 조회를 공유하고, 외부 HTTP 요청은 별도 스레드에서 실행해 Discord 응답을 막지 않게 했습니다.

### 실제 운영에서의 제한

알림 메시지를 삭제하거나 푸터를 변경하면 재시작 후 해당 발송 기록을 복구할 수 없어 다시 발송될 수 있습니다. 메시지 기준 방식의 한계입니다. 이 문제까지 막으려면 발송 ID를 별도 영구 기록으로 함께 저장해야 합니다.

유튜브 RSS가 반환하는 최근 목록 범위 안에서만 확인합니다. 봇을 오래 꺼 두어 목록에서 사라진 항목은 복구하지 못합니다. 등록 당시 목록 밖의 오래된 항목이 나중에 재등장하면 새 항목으로 판정할 수 있습니다. 유튜브 @핸들 해석은 채널 페이지 메타데이터에 의존하며 실패 시 UC 채널 ID 또는 `/channel/UC…` 주소로 등록하세요. 공개 영상이 없는 채널은 현재 등록할 수 없습니다.

이 봇은 **한 프로세스만 실행**해야 합니다. 여러 프로세스가 같은 채널을 동시에 처리하면 중복 발송될 수 있습니다. Discord가 메시지를 수락했지만 HTTP 응답이 유실되는 상황 등에서 절대적인 1회 발송 보장은 하지 않습니다.

## 데이터 및 확인 주기

`data/subscriptions.sqlite3`에는 서버·채널·소스·등록 기준 메시지 ID와 등록 당시 목록만 저장합니다. 재시작과 배포 시 이 파일을 유지하세요. Pterodactyl 등에서도 영구 저장 영역에 두세요. 경로를 바꾸려면 `BOT_DATA_DIR`을 설정합니다.

이전 `last_video.txt`는 사용하지 않습니다. 기존 환경변수로 지정한 채널은 자동 이관하지 않으므로 실행 후 명령어로 다시 등록하세요. 등록 시 최신 영상 한 건만 확인용으로 표시합니다. 기존 SQLite 유튜브 구독과 발송 기록 형식은 유지하며, 지원하지 않는 종류의 구독은 목록과 자동 발송에서 제외합니다.

기본 확인 주기는 60초이며 `CHECK_INTERVAL`로 조정합니다. 최소 주기는 30초입니다.

## 검증

`python test.py`

네트워크 없이 목록 순서 변경·과거 항목 재등장, 서버/소스별 격리와 재시작, 메시지 작성자와 소스 판별, 기록 조회 실패 시 발송 중단, 일부 발송 후 재시도를 검증합니다. 원래 `test.py`에 있던 하드코딩 API 키는 제거했습니다.

실제 토큰으로 로그인하거나 Discord 메시지를 보내는 실서버 검증은 수행하지 않았습니다. 운영 전에 별도 테스트 채널에서 등록·해제·권한 거부·재시작을 확인하세요.
